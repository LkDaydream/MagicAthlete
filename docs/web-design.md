> 本文档为**最终确认版**设计说明，用于指导实现。基于已批准的《魔法运动员 Web 联机棋盘方案》，并按最新拍板结论更新。

## 1. 定位与范围

- 本项目用于**与朋友联机游玩**，本质是一个**可交互、可实时同步的棋盘**，**不是**规则引擎。
- **不做任何业务判断**：棋子移动、角色技能发动、名次、计分等，**全部由玩家真人 + 连麦自行裁定**。
- 系统只做三件事：
  1. 提供**可交互的棋盘**（拖拽棋子、吸附到格、自定义格子改色）；
  2. 提供**掷骰**（服务端下发点数，全员一致）；
  3. 把「谁把棋子移到了哪」**实时同步**给房间内所有人。
- **临时房间、免登录**；对局状态存于服务端内存。

## 3. 架构总览

- **服务器**：Spring Boot + WebSocket。持有房间的**最新棋盘状态**（仅用于同步与断线恢复，**不做规则校验**），收到客户端消息即**广播**给房间内其他成员。
- **客户端**：React + TypeScript。发送自己的操作（拖动中 / 落子 / 掷骰 / 改色 / 撤销 / 重置），并渲染服务器广播的他人操作。

```
Client A ──(drag:move / drag:end / dice:roll / cell:color / move:undo / room:reset)──► Spring Boot (Room)
                                                                                        └──广播──► Client A/B/C
```

服务器只做「校验格式 + 记录最后状态 + 转发」，**不判断移动是否合法**。

---

## 4. 技术选型

- **后端**：Spring Boot 3.3.4（现有），新增 `spring-boot-starter-websocket`；**原生 WebSocket + JSON**（低延迟）；房间用内存 `ConcurrentHashMap`。
- **前端**：React + TypeScript + Vite；**Zustand** 管理房间/棋盘状态；**Pointer Events** 实现拖拽；棋盘用 **SVG + 绝对定位 DOM**（便于吸附与动画）。
- **托管**：后端静态托管前端构建产物（`src/main/resources/static/`）；开发期用 Vite dev server + 代理 `/ws`、`/board`。
- **测试**：后端 `spring-boot-starter-test` + WebSocket 集成测试；前端 Vitest + Playwright（多客户端实时同步）。

## 5. 核心机制设计

### 5.1 房间与玩家

- 建房 → 生成 4 位**房间码**（排除易混淆字符）；玩家用房间码加入；服务器分配**玩家 ID + 颜色**。
- 玩家以客户端 `token` 识别，**断线重连**后复用同一身份并下发**全量快照**。
- 服务器维护 `Room { code, players[], pieces[], cellColors, boardSide, moveHistory }`。

### 5.2 棋盘与棋子

- 赛道 **30 格**（0=起点，29=终点），见 [track.md](./track.md)；以**紧凑配置 + 前端计算坐标**外置，渲染成可吸附的路径。
- 温和/狂野面**仅作视觉切换**；`boardSide` 由房主/任意玩家切换并同步给全员。
- **自定义格子改色**：点击格子 → 选色 → `cell:color` 同步；`color=null` 清除。仅视觉，无任何效果。
- 棋子：每玩家 **1–4 枚**（可配置）；外观为**玩家颜色圆点 + 玩家名**；同格多棋子见 5.6。

### 5.3 拖拽移动（拖拽 + 吸附）

- Pointer Events：按下捕获棋子 → 跟随指针 → 松手**吸附到最近格中心**。
- 吸附统一到格心，保证与渲染坐标一致。

### 5.4 实时同步（拖动过程也同步）

- **拖拽锁**：开始拖动棋子 P 时发 `drag:start`，服务器把 P **锁定给该玩家**；锁定期间他人不可拖（避免冲突）。
- **拖动中**：以**节流**（约 20–30Hz）发 `drag:move {pieceId, x, y}`；服务器转发。
- **接收端平滑**：他人用**插值（lerp）**在两次坐标间过渡，避免跳动。
- **落子**：松手发 `drag:end {pieceId, cell}`，服务器记录并广播最终位置，同时**释放锁**并记入历史。
- **兜底**：拖拽者断线/超时，服务器**自动释放锁**。

### 5.5 掷骰（App 掷骰）

- 客户端发 `dice:roll` → **服务端生成** 1–6 随机点数 → 广播 `dice:rolled {playerId, value}` 给全员。
- 前端展示掷骰动画与结果；玩家据此自行移动棋子（系统**不自动移动**）；保留掷骰历史。

### 5.6 同格多棋子的堆叠与遮盖

- **堆叠布局**：同格棋子**偏移错开（cascade）**摆放，每枚露出可点区域；超过阈值（如 4 枚）收拢并显示**数量角标**（如 `×5`）。
- **层级顺序（z-order）**：按**确定性规则**（玩家加入顺序 / playerId）决定，保证所有客户端层面一致；**本机正在拖动/选中的棋子强制置顶**（仅本地）。
- **选中交互**：偏移摆放让每枚可点；点击堆叠**循环选中**，或悬停/长按**浮起放大**。
- **拖动时**：被拖棋子脱离堆叠置顶跟随指针，同格其它保持原位；落子后重算堆叠。
- **视觉提示**：格子角标显示该格棋子数。

### 5.7 辅助工具（无规则便捷项）

- **重置到起点**：`room:reset`，把所有棋子移回起点（cell 0），清空历史，广播快照。
- **撤回上一步**：`move:undo`，服务器弹出最近一次落子记录并还原其原始格，广播结果。

## 6. 消息协议

统一信封：`{ type, seq, payload }`（JSON）。

| 方向 | 消息 | 载荷 | 说明 |
| --- | --- | --- | --- |
| C→S | `room:join` | token, roomCode?, playerName, piecesPerPlayer? | roomCode 为空则建房；piecesPerPlayer 仅建房时生效 |
| S→C | `room:state` | roomCode, boardSide, players[], pieces[], cellColors{} | 全量快照（重连/初始） |
| C→S | `board:side` | side (`mild`/`wild`) | 切换视觉面 |
| C→S | `cell:color` | cell, color(null=清除) | 自定义格子改色 |
| C→S | `drag:start` | pieceId | 申请拖拽锁 |
| S→C | `piece:locked` | pieceId, lockedBy | 锁状态变更 |
| C→S | `drag:move` | pieceId, x, y | 拖动中（节流） |
| S→C | `piece:dragging` | pieceId, x, y, byPlayer | 转发拖动位置 |
| C→S | `drag:end` | pieceId, cell | 落子 |
| S→C | `piece:moved` | pieceId, cell | 落子广播 |
| C→S | `dice:roll` | — | 请求掷骰 |
| S→C | `dice:rolled` | playerId, value, seq | 掷骰结果 |
| C→S | `move:undo` | — | 撤回上一步 |
| C→S | `room:reset` | — | 重置到起点 |
| S→C | `player:joined` / `player:left` | playerId | 玩家进出（随后补 `room:state`） |
| S→C | `error` | code, message | 错误（如房间不存在） |

## 8. 分阶段路线图

| 阶段 | 目标 | 交付 |
| --- | --- | --- |
| **P0 脚手架** | 打通工程链路 | 前端工程初始化；后端加 WebSocket 依赖；定义 `protocol` 消息类型 |
| **P1 房间与连接** | 能进同一房间 | 建房/加入房间码、玩家列表、`room:state` 快照、断线重连 |
| **P2 棋盘渲染** | 看得见棋盘 | 30 格路径 + 温和/狂野视觉切换 + 自定义格子改色 + 各色棋子（颜色+玩家名）+ 同格堆叠/遮盖 |
| **P3 拖拽移动** | 能拖动棋子 | Pointer 拖拽 + 落子吸附到格（纯本地） |
| **P4 实时同步** | 大家看得见彼此 | 拖拽锁、`drag:move` 节流广播、接收端插值、`drag:end` 落子同步 |
| **P5 掷骰与辅助** | 能掷骰与操作 | 服务端掷骰 + 动画 + 结果广播 + 历史；重置到起点、撤回上一步 |
| **P6 打磨** | 好用 | 移动端触控适配、重连恢复体验、音效/视觉反馈、棋子数量设置 UI |

## 9. 测试与质量

- **后端**：房间加入/退出、消息广播、锁释放、撤销/重置、重连快照的集成测试。
- **前端**：拖拽吸附与堆叠布局单测；Playwright 起 2–3 个客户端验证**拖动中实时可见**、**落子同步**、**改色同步**。
- **验收**：两个浏览器（或一机多标签）能实时看到对方拖动、落子、掷骰与改色；断线重连后棋盘一致。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 拖动实时同步的带宽/抖动 | 节流广播（20–30Hz）+ 接收端插值 + 只传必要字段（pieceId,x,y） |
| 同一棋子被多人同时拖 | `drag:start` 拖拽锁 + 断线/超时自动释放 |
| 同格多棋子互相遮盖、难以选中 | 偏移堆叠 + 数量角标 + 确定性 z-order + 拖动置顶 + 点击循环选中 |
| 服务器单点 | 朋友自建场景可接受；房间状态在内存，进程重启即清空 |
| 棋子与格对齐误差 | 统一吸附到格心；渲染坐标与格心共享同一套布局数据 |
| 无规则校验导致"乱来" | 符合预期——真人裁定棋盘；配「重置/撤回」辅助 |

## 11. 假设与待定

- 后端沿用现有 **Spring Boot** 作为中继（非独立 Node 服务）。
- 掷骰由**服务端**下发（服务器同时作为随机源）。
- 温和/狂野面**仅视觉**，格子上色**仅视觉**，均不产生效果。
- 棋子数量默认 **1**，房主可设为 1–4；房间人数上限 **6**。
- 赛道 30 格及特殊格的排布以配置为准，后续可照实体版图逐格校准。
